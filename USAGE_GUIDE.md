# Руководство по использованию схемы НИОКР / R&D Schema Usage Guide

## Быстрый старт / Quick Start

### Шаг 1: Инициация проекта
1. Скопируйте шаблон `01_Initiation/project_charter_template.md`
2. Заполните основную информацию о проекте
3. Определите цели, задачи и заинтересованные стороны
4. Получите утверждение от спонсора проекта

### Шаг 2: Определение требований
1. Используйте шаблон `Documentation/Requirements/technical_specification_template.md`
2. Документируйте все требования к проекту
3. Согласуйте требования с заказчиком

### Шаг 3: Планирование
1. Создайте план управления проектом в `02_Planning/`
2. Используйте шаблон `02_Planning/risk_register_template.md` для управления рисками
3. Определите график работ и бюджет

### Шаг 4: Выполнение НИОКР
1. Проводите исследования в папке `Research/`
2. Разрабатывайте решения в `Development/`
3. Тестируйте в `Testing/`
4. Документируйте процесс в `03_Execution/`

### Шаг 5: Мониторинг
1. Регулярно обновляйте статус в `04_Monitoring/`
2. Отслеживайте метрики и показатели
3. Контролируйте качество

### Шаг 6: Завершение
1. Используйте шаблон `Documentation/Reports/niokr_report_template.md`
2. Подготовьте итоговый отчет
3. Проведите приемку работ
4. Сохраните извлеченные уроки в `05_Closure/`

## Рекомендации по документированию / Documentation Best Practices

### Именование файлов / File Naming
- Используйте понятные имена файлов
- Формат: `YYYY-MM-DD_название_документа.md`
- Пример: `2024-01-15_project_charter.md`

### Контроль версий / Version Control
Каждый документ должен содержать:
```markdown
**Версия:** X.Y
**Дата:** YYYY-MM-DD
**Автор:** ФИО
**Статус:** [Черновик/На согласовании/Утвержден]
```

### Структура документа / Document Structure
1. Заголовок и метаданные
2. Содержание (для больших документов)
3. Основная часть
4. Приложения (при необходимости)
5. Подписи и утверждения

## Типичные сценарии использования / Common Use Cases

### Сценарий 1: Новый НИОКР проект
```
1. 01_Initiation/project_charter.md - создать устав
2. Documentation/Requirements/technical_specification.md - ТЗ
3. 02_Planning/work_breakdown_structure.md - план работ
4. Research/ - начать исследования
5. 03_Execution/work_log.md - вести журнал
```

### Сценарий 2: Подготовка отчета о НИОКР
```
1. Собрать материалы из Research/, Development/, Testing/
2. Использовать Documentation/Reports/niokr_report_template.md
3. Заполнить все разделы согласно ГОСТ 7.32-2017
4. Добавить результаты в Results/
5. Подготовить презентацию в Documentation/Presentations/
```

### Сценарий 3: Управление изменениями
```
1. Зафиксировать запрос на изменение в 03_Execution/change_requests/
2. Оценить влияние на проект
3. Обновить 02_Planning/risk_register.md
4. Получить одобрение
5. Внести изменения в план
```

## Частые вопросы / FAQ

**Q: Нужно ли использовать все папки?**  
A: Нет, используйте только те папки, которые применимы к вашему проекту.

**Q: Можно ли изменять структуру?**  
A: Да, адаптируйте схему под свои нужды, сохраняя основные принципы.

**Q: Какой формат файлов использовать?**  
A: Рекомендуется Markdown (.md) для простоты и контроля версий.

**Q: Как часто обновлять документы?**  
A: Регулярно, в соответствии с планом коммуникаций проекта.
